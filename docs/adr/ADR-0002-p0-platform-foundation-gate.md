# ADR-0002: P0 公共平台底座与业务准入门

- 状态（Status）：Accepted
- 日期：2026-06-30
- 关联设计：`prd/DEEP_RESEARCH_内部AI资产管理平台设计.md` 第 5、11、15、16 章
- 前置 ADR：`ADR-0001-technology-baseline.md`

## 背景（Context）

P0-A 工程基线完成后，仓库提前进入了 P1 资产目录开发。当前资产 CRUD、检索、Gitea 建仓和前端页面已经存在，但身份主体仍为空，后端资产策略允许全部可见性，前端默认授予全部 Scope；字典、受控标签、审计、可靠任务等公共能力尚未落地。

继续在此基础上扩展版本、上传、发布或 Agent 能力，会把临时字符串、开放权限和分散横切逻辑固化到更多模块。后补公共能力将产生接口、数据和授权语义的重复整改，因此需要重新建立 P0 公共底座及业务准入门。

## 决策（Decision）

### P0 分层与准入

P0 分为两个工作包：

1. **P0-A 工程基线**：工程、契约目录、Compose、Flyway、CI、ArchUnit 和健康检查，状态为已完成；
2. **P0-B 公共平台底座**：设计第 5 章全部能力、最小组织/项目作用域及管理端，状态为当前阶段。

P0-A、P0-B 的退出条件全部满足前，P1 资产目录只允许公共底座接入和安全整改，不允许新增业务能力。P2-P5 同样只能消费已完成的公共能力，不得建立临时替代实现。

### 本地用户与 JWT

- PostgreSQL 是平台本地用户、凭据状态、角色绑定、Token 版本和刷新令牌吊销记录的权威事实源。
- 人类用户、Agent、Service、API Client 均通过受控凭据换取平台签发的 JWT；REST、Web 和 MCP 使用统一 Bearer JWT 认证。
- 访问 JWT 使用带 `kid` 的非对称签名，默认 15 分钟；刷新 JWT 默认 7 天并轮换，数据库只保存 `jti`/Token Family 摘要和生命周期状态。
- JWT 只承载身份、Token 版本和粗粒度 Scope。角色、ACL、资源状态、敏感级别等细粒度判断由后端 `AuthorizationService` 实时完成。
- 浏览器访问令牌只驻留内存，刷新令牌使用安全 Cookie；任何 Token 都不得进入 LocalStorage、日志、埋点、错误上报、Git 或测试 Fixture。
- 当前决策不把平台定义为 OIDC Provider。未来 Gitea/企业 SSO 需要单独 ADR。

### 字典与受控标签

- 稳定流程状态继续由代码 Enum 和数据库约束管理；可运营分类由统一字典管理。
- 标签是独立治理对象，具有 `PLATFORM`/`ORGANIZATION` 作用域、稳定 `tagId`/`tagCode`、状态和国际化元数据。
- 资产通过关联表引用标签，写接口提交 `tagIds`；业务模块不得接受未登记自由标签或建立私有标签表。
- Owner 必须引用 Principal/Team ID；License、Framework、Task 等治理字段必须引用有效字典 `itemCode`。

### 公共能力完整范围

P0-B 必须交付身份与用户、授权、组织作用域、字典/国际化、标签、配置、ID/上下文/响应、异常、幂等与任务、日志与审计、通知、观测以及公共管理 API/页面。通知至少验证站内通知和签名 Webhook；邮件、企业 IM、Agent Callback 使用统一适配契约，可在供应商确定后接入。

### 迁移策略

现有 `V1`、`V2` Flyway Migration 不得修改。公共表、资产标签关联、Owner/字典引用和遗留 JSON 数据的整改只能通过 `V3+` 前向迁移完成，并提供存量数据清点、回填、验证和兼容窗口。

P0-B 目标 OpenAPI 对冻结中的资产契约有三项有意的不兼容收紧：所有既有业务端点要求 Bearer JWT；标签查询参数由 `tag` 改为 `tagId`；资产写请求由自由 `tags` 改为受控 `tagIds`。P1 整改必须在同一变更中同步后端、前端、契约测试和数据迁移，不得让旧开放契约继续作为生产兼容承诺。

## 影响（Consequences）

### 正面

- 后续模块共享同一主体、授权、治理数据、审计和可观测语义。
- 资产数据在进入版本、上传和发布阶段前完成受控引用整改。
- 安全失败采用默认拒绝，消除空主体、全 Scope 和 allow-all 策略进入可部署环境的风险。
- 公共能力具备独立契约与测试，可由 REST、MCP 和 Worker 复用。

### 代价与约束

- P1 暂停功能扩展，现有资产实现需要在 P0-B 后通过前向迁移和契约调整整改。
- 本地身份与 JWT 带来密码策略、签名密钥轮换、刷新重放检测和吊销运维责任。
- P0-B 范围扩大，阶段推进改为退出条件驱动，不再依赖固定周数。
- 违反公共能力边界、改变身份事实源或标签治理方式时，必须新增 accepted ADR。
