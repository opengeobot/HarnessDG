# ADR-0001: 技术路线基线与事实源边界

- 状态（Status）：Accepted
- 日期：2026-06-29
- 关联设计：`prd/DEEP_RESEARCH_内部AI资产管理平台设计.md` 第 0、3、4、15 章
- 作者：AxeXie

## 背景（Context）

内部 AI 资产管理平台需要统一登记、检索、授权、发布和分发模型与数据集。资产信息天然分布在
代码仓库、对象存储、数据版本工具和业务数据库中，如果不预先约定"谁是权威事实源"，多份数据
会逐步漂移，导致版本不可信、权限漂移、内容无法复现。

平台首期不建设训练与在线推理能力，核心诉求是：以可审计、可复现的方式确定一个不可歧义的资产
版本，并对人类用户、CLI、REST、MCP/Agent 提供同一套授权与审计语义。

设计文档已经给出明确的技术分工与事实源矩阵，本 ADR 将其固化为不可在无新 ADR 情况下推翻的
架构基线。

## 决策（Decision）

### 技术路线基线

平台采用以下固定技术分工，作为后续所有实现的强制约束：

- **Gitea**：拥有 Git 仓库、代码、资产卡片（`README.md`/`asset.yaml`）、清单、配置、DVC 指针、
  Git Commit 与 Git Tag。Commit/Tag 是可审计的版本锚点。
- **DVC**：拥有模型权重、数据集目录、多模态文件等大文件的内容版本与可复现依赖；通过内容
  寻址生成摘要，将大文件从 Git 历史中剥离。
- **MinIO**：作为对象存储数据面，承载 DVC Remote、上传暂存区（`asset-staging`）、预览产物
  （`asset-preview`）以及可选的 Gitea LFS/附件对象。
- **PostgreSQL**：存储工作流状态、授权、任务、审计与查询投影（资产/版本检索投影、Outbox、
  Inbox、幂等记录等）。它是查询与流程投影，不替代 Git/DVC 的版本事实。
- **业务控制面**：采用 **Java 21 + Spring Boot + MyBatis-Plus**，作为唯一业务控制面，负责业务
  API、权限、发布工作流、搜索索引、Gitea/MinIO/DVC 编排、MCP Server 与审计。
- **前端**：采用 **React + TypeScript**，提供资产发现、详情、上传、版本、审批与接入配置页面。
- **Docker Compose**：作为开发与功能验证基线（本地开发、CI 功能验证、单机 PoC），不伪装为
  高可用生产方案。

### 适配器复用同一应用内核

REST、MCP 与 Worker 仅作为适配器（Adapter），它们 **必须复用同一套应用服务（Application
Service）、授权（AuthorizationService）、状态机与审计逻辑**，不得各自实现第二套业务规则，也
不得绕过授权或直接访问 Mapper。

### 四类事实源矩阵

| 信息类型 | 权威事实源 | 说明 |
| --- | --- | --- |
| 代码、资产卡片、清单、版本标签 | Gitea | Git Commit/Tag 是可审计版本锚点 |
| 模型/数据集实际内容 | DVC + MinIO | DVC Hash 标识内容，MinIO 保存对象 |
| 业务状态、权限、搜索与统计 | PostgreSQL | 查询与流程投影，不替代 Git/DVC 版本事实 |
| 临时上传与预览产物 | MinIO | 有生命周期策略，不属于正式版本 |

PostgreSQL 中的资产/版本投影必须可从 Gitea + DVC 重建；正式版本由
`Git Tag + Commit SHA + Manifest/DVC Digest` 共同确定。

## 影响（Consequences）

### 正面

- 版本事实可验证、可复现，避免多事实源混乱。
- 控制面、数据面、版本面职责清晰，后端不重造 Git/DVC，不代理大文件数据流。
- 人类与 Agent 共享同一权限与审计模型，降低越权与泄密风险。
- 适配器复用同一应用内核，避免 REST/MCP/Worker 行为分叉。

### 约束与代价

- 后端不得替换 Gitea + DVC + MinIO 技术路线，也不得新增 Python 业务服务绕过 Java 控制面。
- 不得更改上表所定义的事实源边界（例如把发布状态写回 Gitea 作为权威、或让 PostgreSQL 成为
  内容版本事实源）。
- Web 上传会产生"暂存对象 → DVC 内容寻址对象"的一次内部搬运，需通过限额与 CLI/DVC 引导
  控制成本。
- DVC 依赖 Python 运行时，仅由受控 Worker 镜像携带并锁定版本，业务编排仍由 Java 实现。

### 变更治理

**不得在没有新增并被接受的 ADR 的情况下，替换上述技术路线或更改任一事实源边界。** 任何涉及
技术栈、模块边界、事实源、发布语义或安全模型的变化，必须新增 ADR 并同步更新设计文档、契约、
代码与测试；若仅有代码先行而无 ADR，应视为架构违规予以拒绝。
